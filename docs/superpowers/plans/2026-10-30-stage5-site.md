> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `data/public/` JSON만 읽는 정적 사이트 4페이지(오늘의 경기 / 팀 / 선수 / 모델 성적표)를 `site/`에 만들어 GitHub Pages로 띄우고, 같은 페이지를 Genspark로 제작할 수 있는 브리프(목업·데이터 계약·디자인 토큰·체크리스트)와 내보내기 반영 절차를 갖춘다. 푸터 증거 바(마지막 갱신·Actions 실행·커밋·모델)가 모든 페이지에 있다.

**Architecture:** 빌드 없는 정적 HTML + CSS + 바닐라 ES 모듈. `site/assets/tokens.css`가 `DESIGN_clay.md` 토큰을 CSS 변수로 옮기고, `site/assets/app.js`가 데이터 계층(`DATA_BASE` 자동 선택: localhost면 `../data/public`, 아니면 raw.githubusercontent.com)·팀 이름/색·숫자 포맷·공통 내비/푸터 렌더를 제공한다. 차트는 외부 라이브러리 없이 인라인 SVG를 JS로 그린다(토큰 색 그대로 쓰기 위해). 홈은 `status.json.mode`가 `rewind`이거나 오늘 경기 파일이 없으면 2026 되감기 슬라이더로 바뀐다. `.github/workflows/pages.yml`이 `site/`를 GitHub Pages에 배포한다. Genspark 제작본은 검증 스크립트를 통과하면 `site/`를 대체한다(그 전까지 Pages는 이 계획의 버전).

**Tech Stack:** HTML5, CSS(변수·grid·clamp), ES2020 모듈, 인라인 SVG, 폰트 Inter(Google Fonts) + Pretendard(jsDelivr) — 외부 리소스는 이 둘뿐. 검증은 Python(beautifulsoup4, pytest). 배포 `actions/configure-pages@v5`·`upload-pages-artifact@v3`·`deploy-pages@v4`.

**Spec:** `docs/superpowers/specs/2026-10-27-kbo-predict-design.md` §8(데이터 계약), §9(웹사이트), §12 item 5. 디자인 시스템 `DESIGN_clay.md`, 확정 목업 `.superpowers/brainstorm/860-1793099185/content/clay-hybrid.html`(Task 1에서 `docs/design/clay-hybrid.html`로 복사). 이월: `docs/superpowers/plans/2026-10-27-stage0-deferred.md` "5단계(사이트) 전에".

## 계획 시점의 판정

- **먼저 `site/`를 완성하고 Pages로 띄운 뒤 Genspark 브리프를 준다.** Genspark 확인(fetch·내보내기)이 됐으므로 스펙 §9 원안대로 Genspark 제작이 목표지만, 제작·피드백은 사용자의 시간이 들므로 완성된 참조 구현을 먼저 둔다. Genspark 제작본이 검증(Task 6의 `check_site.py`)을 통과하고 사용자가 더 마음에 들면 `site/`를 교체한다. 바꾸지 않아도 사이트는 이미 공개돼 있다.
- **차트는 인라인 SVG**(Chart.js 등 미사용): 토큰 색·폰트를 그대로 쓰고 외부 의존을 0으로 유지한다. 종류: 신뢰도 곡선(막대+대각선), 시즌 적중률 누적선, 선수 유형 산점도(PCA x,y), 팀 유형 구성 누적 막대, 요인 막대.
- **2D 지도는 PCA 좌표**(`players.json`의 `x`,`y`; 목업의 "UMAP"은 PCA로 표기).
- **`DATA_BASE` 자동 선택**: `location.hostname`이 `localhost`/`127.0.0.1`이면 `../data/public`, 아니면 `https://raw.githubusercontent.com/kimminseo2323-prog/2610_KBO_predict/main/data/public`. 모든 fetch에 `?v=<Date.now()>` 캐시 버스트(raw는 CDN 캐시 5분).
- **되감기 전환 규칙**: `status.json.mode === "rewind"` → 홈은 `rewind/2026/index.json`의 마지막 날짜로 시작하고 날짜 슬라이더 표시. `mode === "live"`면 `latest.json`을 보여 주되, 상단에 "2026 시즌 되감기" 토글을 둔다(언제든 볼 수 있게).
- **포스트시즌 보정 항목은 요인 카드에 넣지 않는다**(모델 항 아님, 스펙 §4.3). 요인 카드는 `factors` 5개 그대로.
- **선수 페이지 기본 시즌은 가장 최근 시즌(2026)**, 그룹 기본 타자, 팀 필터 전체. 선수 선택은 URL 해시(`#b-2026-2949`)로 공유 가능.
- **팀 페이지 기본 시즌 2026**; `model_expected`가 null인 시즌은 열을 "—"로.
- **라이브 기록 표**(홈·성적표)는 `history.csv` 전부를 읽어 `model_version`별 적중률을 보여 준다. 행이 적을 때(지금 2행) "라이브 기록은 10월 말 시작"을 명시.
- **Genspark 브리프**는 페이지당 하나의 프롬프트 + 공통 규칙 + 수락 체크리스트. 사용자는 Genspark에 `site/` 파일과 브리프를 함께 넣고 "이 구조·데이터 연결을 유지하되 더 완성도 높게"로 요청한다.
- **내보내기 반영**: `scripts/import_site.py <폴더|zip>` → `site/`로 복사하면서 Cloudflare beacon 등 허용되지 않은 외부 스크립트 제거, 상대 경로 점검, `check_site.py` 실행. 통과 시 커밋(컨트롤러).
- `site/`는 Pages 전용이며 Actions 일일 커밋 대상이 아니다(`daily.yml`의 `git add data/raw data/public` 그대로).
