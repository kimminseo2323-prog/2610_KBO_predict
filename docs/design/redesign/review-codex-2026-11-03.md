# KBO Predict 디자인 전수 검토 수정 리스트

## 높음

1. **선발 미정 경기의 확률 신뢰도 표시가 과함**
   - 페이지·상태·폭: `home-edge` 정상/선발 미정 · PC·모바일
   - 위치: 경기 카드 `.matchup`, `home.js → sideBlock()`
   - 문제: `home-edge-1280-00.png`, `home-edge-390-01.png`에서 선발 미정인 키움–KT 경기에도 `35% / 65%`가 일반 경기와 동일한 시각적 강도로 표시된다. 사용자는 선발 정보가 반영된 예측으로 오해할 수 있다.
   - 제안 수정: 확률 숫자 옆에 `선발 미정 기준` 또는 `선발 입력 전`을 명시하고, 숫자 불투명도를 0.65 이하로 낮춘다. `선발 미정` 상태에서는 모델 신뢰도 경고를 경기 카드 상단에 고정한다.
   - 심각도: 높음

2. **모바일 팀 순위표가 지나치게 압축됨**
   - 페이지·상태·폭: `teams` · 모바일
   - 위치: `.standings`, `teams.css @media (max-width: 639px/599px)`
   - 문제: `teams-390-00.png`, `teams-390-01.png`에서 순위, 팀, 승-패-무, 승률, 피타고리안, 모델 값이 한 화면에 모두 들어가며 일부 값이 12~15px 수준으로 축소된다.
   - 제안 수정: 모바일에서는 기본 열을 `순위·팀·승률·모델`만 노출하고 승-패-무·피타고리안은 행 탭/상세 패널로 이동한다. 현재처럼 모든 열을 억지로 맞추지 말고, 최소 행 높이 `48px`, 본문 숫자 `16px`을 유지한다.
   - 심각도: 높음

3. **모바일 경기 카드가 팀별 색 면을 세로로 분리하면서 경기 단위 인지가 약해짐**
   - 페이지·상태·폭: `home-live`, `home-regular-rewind`, `home-edge` · 모바일
   - 위치: `.matchup`, `.side--away`, `.side--home`
   - 문제: `home-live-390-00.png`, `home-regular-rewind-390-00.png`에서 원정/홈 면이 화면을 거의 각각 한 장씩 차지한다. 두 팀의 대결 관계와 VS 관계가 데스크톱보다 약하게 보인다.
   - 제안 수정: 모바일에서도 중앙에 작은 `VS` 또는 얇은 사선 경계 띠를 유지한다. 각 팀 영역 높이를 현재보다 15~20% 줄이고, 경기 카드 전체를 하나의 `matchup`으로 묶는 공통 상단 띠를 강화한다.
   - 심각도: 높음

## 중간

4. **승률 우세 팀의 강조 규칙이 모든 하위 컴포넌트에 일관되게 적용되지 않음**
   - 페이지·상태·폭: 홈·라이브/정규/검증 경기 · PC·모바일
   - 위치: `home.js → renderFactors()`, `renderOutlook()`, `.ticker__item`, `.race`
   - 문제: 메인 경기 카드는 우세 팀 숫자를 팀 색으로 보여주지만, 요인 차트와 일부 하위 확률 표기는 `홈/원정 방향` 또는 검정색을 기준으로 표현한다. 사용자가 “우세 팀 색”과 “홈/원정 색”을 혼동할 수 있다.
   - 제안 수정: 색상 역할을 명확히 분리한다.  
     `팀 카드·승률 숫자 = 우세 팀 색`, `요인 차트 = 홈/원정 방향 색`, `설명문 = 검정/회색`. 차트 제목에 `홈 기준 + / 원정 기준 -`를 고정 표기한다.
   - 심각도: 중간

5. **빈 공간이 카드 높이 차이로 반복 발생**
   - 페이지·상태·폭: 홈·검증/정규 · PC
   - 위치: `.home-bento`, `.b-factors`, `.b-outlook`, `.b-starters`, `.b-typemap`
   - 문제: `home-edge-1280-01.png`, `home-regular-rewind-1280-01.png`에서 왼쪽 카드의 콘텐츠가 짧게 끝나도 행 높이가 옆 카드에 맞춰져 큰 빈 영역이 생긴다.
   - 제안 수정: 동일 행의 카드 높이를 강제로 맞추지 말고 `align-items: start`를 적용한다. 긴 콘텐츠는 별도 행으로 분리하거나 `grid-template-areas`를 상태별로 재배치한다.
   - 심각도: 중간

6. **페이지 상단 sticky 내비게이션이 스크롤 콘텐츠를 가림**
   - 페이지·상태·폭: 전체 페이지 · PC·모바일
   - 위치: `.topnav { position: sticky }`, 앵커 이동 및 차트 선택 이동
   - 문제: `home-live-1280-02.png`, `report-1280-01.png`처럼 스크롤 위치에서 첫 줄 콘텐츠가 상단 메뉴 아래에 걸쳐 보인다. `players`의 카드 이동도 동일한 위험이 있다.
   - 제안 수정: 모든 주요 섹션에 `scroll-margin-top: 116px` 정도를 적용하고, 모바일은 `scroll-margin-top: 100px`로 별도 지정한다.
   - 심각도: 중간

7. **홈 모바일의 정보 순서는 개선됐지만 첫 화면에 설명·상태·경기 정보가 과밀함**
   - 페이지·상태·폭: `home-edge`, `home-live` · 모바일
   - 위치: `.home-head`, `.fixture-note`, `.matchups`
   - 문제: `home-edge-390-00.png`, `home-live-390-00.png`에서 제목, 날짜 설명, 버튼, 검증 안내, 경기 메타가 연속으로 쌓여 실제 승률 카드 시작까지 세로 공간을 많이 소비한다.
   - 제안 수정: 검증 안내는 기본 한 줄 요약만 노출하고 상세는 `<details>`로 접는다. 날짜 설명은 제목 아래 한 줄로 통합한다. 모바일에서는 `GitHub` 및 부가 메타를 숨기거나 하단으로 이동한다.
   - 심각도: 중간

8. **취소 경기 상태가 일반 경기와 의미적으로 충분히 구분되지 않음**
   - 페이지·상태·폭: `home-edge` · PC·모바일
   - 위치: `.matchup--canceled`, `home.js → renderMatchups()`
   - 문제: `home-edge-1280-01.png`, `home-edge-390-01.png`의 `한화 vs 롯데`는 회색 박스로 분리되지만, 경기 시간·취소 사유·예측 제외 상태의 우선순위가 명확하지 않다.
   - 제안 수정: 제목을 `한화 vs 롯데 · 취소`로 통합하고, `우천 취소`를 상태 배지로 고정한다. 예측 영역은 아예 제거하고 `예측 없음`을 별도 상태 문구로 표시한다.
   - 심각도: 중간

9. **선수 탐색 모바일에서 선택 카드까지 도달하는 거리가 너무 김**
   - 페이지·상태·폭: `players` · 모바일
   - 위치: `.stage`, `.map-card`, `.player-card`
   - 문제: `players-390-00.png`, `players-390-01.png`에서 산점도, 범례, 설명 접기 후에야 선수 카드가 나타난다. 선택한 점을 눌러도 카드가 자동으로 보이지 않으면 핵심 결과가 화면 밖에 남는다.
   - 제안 수정: 모바일에서는 산점도 아래에 선택된 선수 요약을 먼저 배치하고, 상세 카드로 이어지게 한다. 현재 `players.js → jumpToCard()`를 선택 직후 자동 실행하거나 `선수 카드 보기` 버튼을 선택 결과 바로 아래에 배치한다.
   - 심각도: 중간

10. **산점도에서 선택된 점과 일반 점의 구분이 약함**
    - 페이지·상태·폭: `home`, `players` · PC·모바일
    - 위치: `.c-point`, `charts.js → scatter()`
    - 문제: `home-edge-1280-02.png`, `players-1280-00.png`, `players-390-00.png`에서 점이 많아지면 선택 점을 제외한 점들이 서로 겹친다. 선택 점의 외곽선은 있으나 모바일에서 즉시 식별하기 어렵다.
    - 제안 수정: 선택 점에 `3px` 팀 색 외곽선과 `+2px` 크기 증가를 적용하고, 선택 시 차트 상단에 선수명/유형을 짧게 고정 표시한다. 비선택 점은 선택 상태에서 0.35~0.5 opacity로 낮춘다.
    - 심각도: 중간

11. **차트 hover/tap은 구현되어 있지만 값 표시 방식이 일관되지 않음**
    - 페이지·상태·폭: 차트 전체 · PC·모바일
    - 위치: `charts.js → enableTips()`, `.chart-tip`
    - 문제: 막대·산점도·선 차트마다 tooltip 내용과 선택 상태가 다르다. `lineChart()`는 넓은 투명 hit 영역을 사용해 어느 지점을 선택했는지 시각적 피드백이 부족하다.
    - 제안 수정: 모든 tooltip에 `항목명 / 값 / 단위` 순서를 통일한다. 모바일 탭 시 해당 요소를 `is-selected`로 유지하고, 다른 곳을 탭할 때만 닫는다. 선 차트는 탭한 x축 지점을 강조 표시한다.
    - 심각도: 중간

12. **팀 순위와 홈 경기 카드의 숫자 서식이 페이지마다 다름**
    - 페이지·상태·폭: 전체 · PC·모바일
    - 위치: `fmtPct()`, `fmtRate3()`, `.tape__n`, `.standings td.num`
    - 문제: 홈은 `.562`, `.333`, `59.4%`, 팀 페이지는 `.647`, 플레이오프 확률은 `52%`처럼 같은 확률 계열이 서로 다른 자릿수로 표시된다.
    - 제안 수정: 표시 규칙을 고정한다.  
      예측 확률: `59.4%`  
      승률/비율 테이블: `.647`  
      요인 차이: `+4.9%p`  
      표본이 작은 확률: `약 52%` 또는 `52.0%`
    - 심각도: 중간

13. **메타 문구와 배지가 여전히 템플릿 카드처럼 보임**
    - 페이지·상태·폭: 전체 · PC·모바일
    - 위치: `.pill`, `.pills`, `.tchip`, `.model-badges`
    - 문제: `home-live-1280-00.png`, `home-edge-1280-00.png`, `report-1280-00.png`에서 경기 시간, 모델 전망, 선발 상태, 데이터 출처가 모두 작은 배지로 쌓인다. 사용자가 지적한 “알약 남발”과 “AI가 만든 카드 격자” 인상이 남아 있다.
    - 제안 수정: 배지는 상태값에만 제한한다. 경기 시간은 일반 텍스트, 모델 전망은 한 줄 인라인 라벨, 선발 상태만 배지로 유지한다. 한 영역의 배지는 최대 2개로 제한한다.
    - 심각도: 중간

14. **가운뎃점으로 이어진 메타 문구가 정보 우선순위를 흐림**
    - 페이지·상태·폭: 전체 · PC·모바일
    - 위치: 경기 카드의 `.side__chip`, footer, report 설명, 선수 카드 메타
    - 문제: 캡처 전반에서 `팀 · 선수 · 시즌 · 유형 · 모델`이 가운뎃점으로 연결된다. 모바일에서는 줄바꿈 지점이 불규칙해 읽기 어렵다.
    - 제안 수정: 핵심 메타는 2열 구조 또는 줄바꿈 그룹으로 바꾼다. 예: `팀 / 시즌 / 유형`을 별도 항목으로 분리하고, 상세 설명에서만 가운뎃점을 허용한다.
    - 심각도: 중간

15. **보고서 페이지의 통계 한계와 결론이 모바일에서 분리됨**
    - 페이지·상태·폭: `report` · 모바일
    - 위치: `.stage`, `.stage__ruler`, `.ruler__notes`
    - 문제: `report-390-00.png`, `report-390-01.png`, `report-390-02.png`에서 `+2.7%p`, `p=.215`, 라이브 표본 부족, 설계 목표 설명이 여러 화면으로 분산된다. 핵심 결론을 읽기 위해 긴 스크롤이 필요하다.
    - 제안 수정: 모바일에서는 상단에 `결론 1줄 + 근거 2개 + 주의 1개` 요약을 고정한다. 상세 통계와 설명은 접기 영역으로 이동한다.
    - 심각도: 중간

16. **팀 유형 차트의 모바일 라벨·범례가 길어짐**
    - 페이지·상태·폭: `teams` · 모바일
    - 위치: `.roster`, `stackedBar()`, `.chart-legend`
    - 문제: `teams-390-01.png`, `teams-390-02.png`에서 팀별 막대는 읽히지만 범례와 팀명이 길어지며 차트 사이 간격이 커진다.
    - 제안 수정: 모바일에서는 범례를 차트 바로 위에 고정하고, 팀명은 좌측 고정 열로 둔다. 막대 내부 퍼센트는 폭이 `28px` 미만이면 숨기고 탭 tooltip으로만 제공한다.
    - 심각도: 중간

## 낮음

17. **작은 회색 본문과 부가 설명의 대비가 화면별로 다르게 느껴짐**
    - 페이지·상태·폭: 전체 · PC·모바일
    - 위치: `--muted`, `.card__lead`, `.footer__note`, `.race__sub`, `.starter__note`
    - 문제: 색상 자체는 대체로 양호하지만 `home-live-390-01.png`, `players-390-01.png`, `report-390-02.png`에서는 작은 글자와 회색 배경이 겹쳐 시각적 대비가 낮게 느껴진다.
    - 제안 수정: 본문 설명은 최소 `14px`, 보조 캡션은 최소 `12px`로 유지하고, 회색 배경 위의 `--muted`는 `#4a4d54` 이상으로 통일한다.
    - 심각도: 낮음

18. **팀 색과 모델 유형 색의 역할이 일부 화면에서 충돌함**
    - 페이지·상태·폭: `teams`, `players`, 홈 요인 차트 · PC·모바일
    - 위치: `tokens.css`, `typeColor()`, `TEAMS`
    - 문제: 팀 색과 `파워형·장타 지향형·컨택형·주루형` 색이 같은 화면에 동시에 노출된다. `players-1280-00.png`, `teams-1280-01.png`에서 색상 수가 많아 무엇이 팀 색인지 유형 색인지 즉시 구분하기 어렵다.
    - 제안 수정: 팀 색은 면·좌측 바·우세 확률에만 사용하고, 유형 색은 점·범례에만 사용한다. 동일 카드 안에서 두 체계가 함께 나올 때는 범례 제목을 명시한다.
    - 심각도: 낮음

19. **애니메이션이 일부 화면에서 데이터보다 장식처럼 느껴질 가능성**
    - 페이지·상태·폭: 전체 · PC·모바일
    - 위치: `.standings tbody tr`, `.pcard__type`, `.pcard__name`, `.pcard__meta`, `.live__pips`

## 공통으로 고치면 여러 곳이 한 번에 해결되는 항목

- `app.css`의 `.pill`, `.pills`, `.tchip` 사용을 상태·선발·실시간 표시로 제한한다.
- `tokens.css`에 숫자 표시 규칙과 보조 텍스트 최소 크기를 토큰으로 정의한다.
- 모든 섹션 앵커와 `scrollIntoView()` 대상에 sticky 헤더 높이를 반영한다.
- `charts.js`에서 tooltip 포맷, 모바일 선택 유지, 선택 요소 강조를 공통 처리한다.
- 팀 색과 선수 유형 색을 명확히 분리하고, 우세 팀 확률 숫자·팀명·승수에 동일한 팀 색 규칙을 적용한다.
- 모바일 표는 “축소”보다 “핵심 열 노출 + 상세 열 접기” 방식으로 통일한다.
- `details.more`를 설명·주의사항·검증 안내의 기본 패턴으로 사용해 화면의 긴 문장을 줄인다.
- `home.js`의 경기 상태를 `정상 / 선발 미정 / 취소 / 라이브 / 종료`로 명시적인 상태 토큰으로 통합한다.
- 확률은 `%`, 차이는 `%p`, 비율 테이블은 `.000` 형식으로 통일한다.
