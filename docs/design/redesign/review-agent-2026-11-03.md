### 4. 한화(주황) 면의 글자색 판정 버그로 작은 글자 대비 미달
- **페이지·상태·폭**: 홈 되감기(한화 경기), PC·모바일 둘 다
- **위치**: `home.js teamSideColors()`의 `text = lum > 0.3 ? ink : white`
- **문제**:
  - 한화 #fc4e00의 상대 휘도는 0.261이라 기준 0.3에 못 미쳐 흰 글자가 된다. 흰색 대 주황은 **3.37:1**로, 12~13px "원정"·"한화 이글스"·"한화 승리"가 AA(4.5:1)에 못 미친다.
  - 잉크(#0d0d0f) 대 주황은 **5.76:1**이다. `tokens.css` 주석("SSG 노랑·한화 주황은 잉크")과 실제 결과가 다르다.
  - 근거: `home-regular-rewind-1280-00`, `home-regular-rewind-390-00`(한화 면의 흰 글자).
- **제안 수정**: 밝기 기준 대신 두 후보의 대비를 직접 비교한다.
  `const cW = (1.05)/(lum+0.05), cI = (lum+0.05)/(0.0042+0.05); text = cW >= cI ? "var(--on-dark)" : "var(--ink)";`
  이러면 한화는 잉크, KIA(4.64 대 4.2)는 흰색이 된다. 같은 판정을 `charts.js textOn()`, 팀 칩, 스코어 버그에도 쓴다.
- **심각도**: 높음

### 5. 열세 쪽 큰 확률 숫자(투명도 0.5)가 대비 3:1에도 못 미침
- **페이지·상태·폭**: 홈 전 상태, PC·모바일 둘 다
- **위치**: `home.css .side.is-under .side__num { opacity: 0.5 }`
- **문제**: 큰 글자 기준 3:1을 넘지 못하는 경우가 많다.
  - KIA 면 42%: **1.85:1** (`home-edge-1280-00`, `home-edge-390-00`)
  - 한화 면 47%: **1.76:1** (`home-regular-rewind-1280-00`)
  - LG 면: 2.30:1 **(추측: LG가 열세인 경기일 때)**
  - 삼성 44%: 3.26:1 (`home-live-1280-00`, 겨우 통과)
  - 열세 쪽도 읽어야 할 확률인데 거의 안 보인다.
- **제안 수정**: 투명도 대신 "속이 빈 숫자"로 위계를 준다(중계 그래픽 문법과도 맞다).

  이러면 외곽선 대비가 원래 글자색 대비(≥3.37:1)와 같다. 작은 경기 띠(`.matchup--sm`)는 `-webkit-text-stroke:2px`.

1. **섹션 격자를 "좌우 독립 세로 스택"으로 바꾼다** (`app.css .bento` + 페이지 HTML에 `.bento__col` 두 개, 모바일은 `display:contents`)
   - 해결: 1번(요인 아래 공백), 홈 지도·최근 예측 아래 공백, 26번(성적표 오른쪽 공백), 46번과 7번(같은 원리로 `align-items:start` + sticky).
2. **팀 색 도우미 하나로 통일한다** (`app.js`에 `teamColors(code) → {bg, fg, ink}`)
   - `fg`는 흰색과 잉크 중 대비가 높은 쪽. 이것만으로 한화 버그(4번)가 고쳐진다.
   - `ink`는 흰 바탕 위 글자용 색이다. tokens.css에 `--team-sk-ink:#9a6a00`(4.73:1), `--team-hh-ink:#c43c00`(5.26:1)를 새로 두고, 나머지는 원래 팀 색(KIA 4.64:1 이상)을 쓴다. KT는 잉크와 같아서 글자 대신 칩을 쓴다.
   - 규칙: "우세 팀의 이름·숫자 = `ink` 색, 대표 숫자 = 칩".
   - 해결: 2·3·4·12·15·22·30·34·61번.
3. **우세 판정을 함수 하나로 통일한다** (`favState(p)` → fav, under, tie. tie는 반올림 정수가 같거나 |p−0.5|<0.03)
   - 슬랩, 목록, 상단 칩, 요인 자막이 모두 이 함수를 쓴다.
   - 해결: 6번, 5번의 흐림 범위, 45번.
4. **body에 `word-break: keep-all; overflow-wrap: anywhere`를 넣는다**
   - 해결: 8번, 54번, 모든 페이지의 낱말 중간 줄바꿈.
5. **숫자·날짜 서식기를 `app.js`에 모은다**
   - `fmtProb`(<1%·>99%), `pText`(p < .001), `fmtScore`(1 : 6), `fmtDateShort`(11.3), `fmtRecord`(n<30이면 "3/3")
   - 해결: 10·11·23·37·38·52번.
6. **알약과 가운뎃점을 줄인다**
   - 알약은 상태와 유형에만 쓴다. 메타는 맨 글자, 범례는 바탕 없이, 기록은 "라벨 위 / 숫자 아래" 미니 격자로 쓴다.
   - "·"는 구조(간격·줄·칸)로 대체한다.
   - 해결: 14·16·19·20·50·56·61·62번. "AI가 만든 티"의 대부분이 여기서 줄어든다.
7. **판정 칩을 무채색 두 모양으로 통일한다** (적중 = 잉크 면, 미적중 = 잉크 테두리)
   - 팀 색과 충돌하지 않고 대비 문제도 없어진다. 해결: 13번.
8. **계열색(pink·teal·lavender…)은 선수 유형 전용으로 묶는다**
   - 시즌 띠·피처 중요도·모델 기대 마름모는 잉크·회색 단계로 바꾼다. 해결: 28번, 35번(회색 단계 토큰 `--gray-bar:#8d929a` 추가).
9. **접기 컴포넌트를 하나(`details.more`)만 쓴다**
   - 긴 설명, 기술 용어, 해명 문장은 모두 이 안으로 옮긴다. 해결: 18·25·26·33번. "글이 너무 많다"의 대부분.
10. **아래 여백 토큰을 정리한다** (`main` 48px, `.footer` margin 0)
    - 해결: 21번(모든 페이지).
11. **작은 표시의 모바일 탭 범위를 넓힌다**
    - 산점도는 근접 탐색, 누적 막대는 행 단위 히트, 핍은 `title` 대신 data-tip.
    - 해결: 32·49번과 사용자 지적 7(모바일 탭으로 값 보기).
